# Comfy Asset Hub — 素材庫

ComfyUI内で画像・生成グラフ・可逆圧縮・PNG復元を管理する拡張です。既存Image Browser、ComfyUIのグラフ表示、Pillow/libwebpを使っています。

## 開く

ComfyUIの `custom_nodes/comfy-asset-hub` にこのリポジトリを配置してください。依存するPillow・NumPy・psutil・aiohttpはComfyUIのPython環境を使用します。ビルド済みWeb UIを同梱しているため、利用だけならNode.jsは不要です。ComfyUIを再起動し、ブラウザを再読み込みしてください。**サイドバーの「素材庫」（画像アイコン）を1クリック**で開けます。メニューの **Extensions → 素材庫を開く** と、対応レイアウトでの上部ボタンも利用できます。

旧メニューを使用する場合は、フローティングメニュー内の **素材庫** ボタンから直接開けます。起動・終了だけで編集中のワークフローを置き換えることはありません。

## 閲覧位置の保持

同じブラウザタブで素材庫と画像生成画面を行き来しても、フォルダ・サブフォルダ・検索語・並べ替え・表示形式・ページ・スクロール位置・選択画像を保持します。画像から生成ワークフローを開いて戻る場合も同じです。Shift選択の起点と、検索結果全体の全選択も引き継ぎます。

保持はそのタブのメモリ内です。ブラウザの再読み込み・タブを閉じた後までの閲覧位置の保存は対象外です。再表示時には一覧と処理状態を取得し、操作の対象件数も再計算します。閉じた画面の検索タイマーや遅れて届いた一覧応答は、新しい画面へ反映しません。

## 操作

- **フォルダ追加**：このPCの任意フォルダの絶対パスを入力。登録したフォルダは左上のリストから切り替えられます。画像の移動は不要です。
- **選択**：画像をクリック。**Shift＋クリック**で最後にクリックした画像からの範囲を選びます。保管履歴でも同じです。範囲は表示ページ内です。
- **全選択**：現在の検索結果の画像を、未表示ページも含めて選びます。選択件数とは別に、ボタンへ **圧縮 N件／復元 N件** を表示します。例えば100枚中30枚が変換済みなら「選択100件・変換済み30件（圧縮対象外）」「圧縮70件」「復元30件」。0件の操作は無効です。非表示フィルターを使用中は表示ページ内の選択になります。
- **圧縮 N件**：標準で最大4並列。可逆WebPへ変換し、全画素・生成情報・ICCを照合してPNGを置き換えます。確認画面は出ません。縮まない画像はPNGのまま残します。
- **履歴**：全選択または範囲選択し、**PNGに戻す**。旧版で作った候補は **保管**、不要な候補は **候補破棄**。混在選択ではその操作に対応する状態だけを処理します。
- **PNGで取り出す**：必要な1枚を自動復元してダウンロードします。
- **拡大／グラフ**：カードのボタンから画像の拡大とComfyUIのグラフ読込。Wキーはフォーカス中の画像のグラフを読み込みます。

表示した対象リストをそのまま操作へ渡します。待ち行列に入っている間に変換済みになった画像は再圧縮せずスキップします。復元したPNGを再び圧縮する場合は新しい圧縮対象になります。

処理中も選択できます。追加操作は待ち行列に入り、順に実行します。**一時停止**は処理中の画像が終わった時点で止まり、待ち行列も一時停止します。未処理分は保存され、**再開**で続行できます。進捗・エラーは画面内に表示し、本拡張の右上通知は出しません。

## 処理モードと再開

進捗の左の **処理モード** から選びます。初期値は **通常** です。

- **通常**：指定した並列数で処理し、CPUの配分をOSに任せます。CPU使用率を理由に並列数を減らしません。
- **他作業優先**：指定並列数のまま、Windowsの圧縮子プロセスを低優先度で起動します。空いているCPUは使い、他の処理と競合するときはOSに譲らせます。ComfyUI本体の優先度は変更しません。現時点ではWindowsのネイティブコーデックだけが対象で、他OSのPillow経路では通常と同じです。
- **CPU目標 30・50・70・90%**：PC全体のCPU使用率の目安を指定したい場合だけ使います。従来の並列数調整を有効にし、子プロセスの優先度は通常にします。2秒間隔・±5ポイントの許容幅・増減幅は経験則で、厳密な使用率上限ではありません。

隣の **CPU使用率 ○%** はPC全体の実測値です。全モードでメモリ1GiB未満・ディスク容量不足では新規投入を待ちます。生成キューの有無だけでは停止しません。

モードと並列数は実行中・待ち行列に反映し、再起動後も保存します。プロセスの優先度変更は次の画像からで、処理中の画像は完了させます。旧版で明示して保存したCPU目標は引き継ぎ、旧「全速」は通常になります。旧版の暗黙の初期値70%だけではCPU目標モードへ移行しません。以前に目標を保存した場合、OSへ配分を任せるには **通常** または **他作業優先** を選んでください。

ComfyUI終了・強制終了後も対象と画像ごとの完了記録は残ります。再起動後は一時停止状態になり、**処理履歴 → 再開**で残りを処理できます。完了済み画像は再変換しません。待機中にサイズ・更新日時・ファイル識別子が変わった原本は処理を止め、失敗として記録します。

**処理履歴**では処理ごとの進捗と、全件の失敗理由を確認できます。失敗の一覧は100件ずつ表示します。残りの処理を終えた後、**失敗分を再試行**で失敗した画像だけをやり直せます。破損ファイルなどを修正した後の再試行にも対応します。

## 再圧縮の回避と空き容量

64MiB以下のPNGは、容量見積もりで読んだ入力をRAMで次の圧縮へ渡し、原本の全読み込みを1回減らします。投入待ちの先読みは最大1枚・64MiBで、処理開始後は従来必要だった入力バッファとして使い、準備完了・失敗時に解放します。この引継ぎで保持する入力は処理中と投入待ちを合わせて最大（並列数＋1）×64MiBで、展開画素などのメモリは別です。上限を超えるPNGは従来のストリーム走査と読込に戻ります。見積もり後の原本変更、変換後と削除前の原本ハッシュ、画素・生成情報・色プロファイルの照合は維持します。

圧縮しても容量が減らなかった画像は **削減なし（原本保持）** と表示し、次回の全選択でも圧縮対象から外します。原本のファイル情報または圧縮エンジンが変われば再評価対象になります。一覧ではファイル情報を比較するため、フォルダ内の画像をすべて読み込む必要はありません。古い指定などで直接再実行された場合は、原本のSHA-256も照合してから圧縮結果を再利用します。結果は再起動後も保持されます。旧版で破棄済みの候補にはこの記録がないため、一度は再評価されます。

バッチ処理の開始前に、一時領域・保管記録・保存先の必要容量を見積もります。同じドライブなら合算し、別ドライブならそれぞれ確認します。並列実行中の見積量と64MiBの余裕を含めて不足する場合は、次の画像を投入せず **空き容量待ち · 必要○MB / 空き○MB** と表示します。空きが戻れば自動続行し、一時停止・再開も可能です。圧縮だけでなく一括復元にも適用し、通常・他作業優先でも有効です。

容量は予約ファイルを作らない見積もりです。他アプリによる書き込みや見積もり超過による書き込み失敗まで防ぐものではありません。失敗時には原本を保持して理由を記録します。単独の「PNGで取り出す」はこの待機制御の対象外です。

## Viewと並列数

**大きい画像・小さい画像・詳細一覧** を右上で切り替えます。詳細一覧では、サムネイル、ファイル名、寸法、保管状態、容量の変化、削減量を横並びで確認できます。表示方法は次回も保持されます。

画像の **圧縮／PNGに戻す** をその場で実行できます。複数選択して上部のボタンから一括操作することもできます。履歴を開く必要はありません。履歴にもサムネイルを表示します。

並列数は **1・2・4・8・16** から選択し、実行中にも変更できます。標準は4。CPU目標モードでは上限として使います。進捗の **4/16並列** は「実行中4枚・指定上限16枚」です。実行中の画像数、進捗バー、枚/秒、処理中のカード表示を更新します。画像コーデックはCPUで動作し、GPUは使用しません。同一画像の操作は直列にし、DB更新・キャッシュ管理の短い区間だけをロックします。

**CPU使用率** はPC全体の負荷で、画像の処理進捗ではありません。上下するのが通常です。**全体** のバーは処理済み件数を示します。その下の **処理中の画像** では、画像名・工程・経過秒数を同じ画面で確認できます。一覧は折りたため、同じタブでの開閉状態を保持します。

Windows版の「圧縮中 ○%」はcwebp自身が返す進捗です。圧縮が100%になった後も生成情報の保存・照合・ファイル保存が続きます。読み込み・照合・保存・PNG復元や、数値を取得できない圧縮経路は工程名だけを表示し、全工程の推定％は作りません。画像が切り替わると、その画像の進捗に切り替わります。

速度表示は **直近約30秒の完了枚数÷実時間** です。失敗・既処理スキップは含めず、資源待ちの時間は含めます。画面を開いて5秒間は「速度計測中」とし、再開・別ジョブ・長い取得中断では測り直します。以前の「累計件数÷累計時間」は、過去の設定や待機の影響で現在の速度を反映しませんでした。

通常の進捗更新は履歴・容量集計を取得せず、履歴を開いたときだけ取得します。履歴の新着順には専用索引を使い、大きなメタデータDBの全件走査を避けます。更新後のComfyUI再起動時に既存DBにも索引を作成します。実行中の圧縮は一時停止してから再起動し、ブラウザーを再読み込みした後に処理を再開してください。

Windows x64では同梱の公式 `cwebp.exe` / `webpmux.exe` 1.6.0を使用します。操作バーの **圧縮方法** で次の2つを選べます。

- **サイズ優先（既定）**：m1/q50。速度優先を導入する前の設定に戻しています。
- **速度優先**：m1/q20。探索量を減らすため速くなる場合がありますが、容量が増える場合があります。

どちらも可逆圧縮で、画素・透明部分RGB・生成情報・ICCを照合します。「サイズ優先」は最小容量の保証ではなく、画像によって大小が逆転する場合もあります。失敗時は別方式へ自動で切り替えず、原本を残します。コマンドごとの制限時間は300秒。実際に使った設定と時間は各画像の保管記録 `encoding` に残ります。

設定は再起動後も保持します。処理中の変更は **次に処理を開始する画像から** 反映します。すでに圧縮中の画像は開始時の設定で完了し、待機中の画像・ジョブと一時停止後の再開には現在の設定を使います。既存WebP・作成済み候補は再圧縮しません。「削減なし」の判定は設定ごとに区別し、別設定で選び直したPNGは再評価します。非Windows x64のPillowではサイズ優先が従来のm4/q80、速度優先がm1/q20です。他OSでの速度改善率は未検証です。


## 画像同士の関連図

表示切替の **関連図** を押します。画像を1枚選ぶと、その画像を中心に現在のフォルダ・検索結果全体から近い画像を探します。2枚以上を選んでいる場合は選択画像だけを比較します。非表示フィルターを使用中は表示ページの画像だけを対象にします。

- **総合／共通プロンプト／見た目** を切り替えられます。緑の線は共通語句、黄色は見た目、紫は両方です。
- 画像や線をクリックすると、比較する2枚・共通語句・色調/配置/輪郭の近さを同じ画面に表示します。
- **この画像を中心に** で関連を辿れます。画像のドラッグ、背景のドラッグ、ホイール拡大縮小、**全体表示** に対応します。
- 関連画像は20枚ずつ表示します。**次の20枚／前の20枚** で続きも確認できます。フォルダの解析対象が20枚に制限されるわけではありません。

初回は画像を1枚ずつ解析します。途中からグラフを表示し、**解析を停止／解析を再開** も可能です。閉じると残りの解析を止めます。解析済みの特徴は `asset-hub/relations.sqlite3` に保存し、再度開いた際はファイル情報が変わっていない画像を再利用します。静止画のPNG・WebP・JPEGなどが対象で、アニメーションは対象外です。解析で元画像を変更したり、編集中のComfyUIワークフローを置き換えたりはしません。

**見た目の比較は色調・配置・輪郭です。人物名・服の種類などの意味認識や、プロンプトの類義語判定は行いません。** 画像特徴モデルや外部サービスは使いません。ComfyUIの生成データを辿って正のプロンプトを抽出し、判別できない形式は「抽出テキスト（正負不明）」と明示します。既存カードの **グラフ** は生成ワークフローを開く機能で、この関連図とは別です。

## 大量フォルダ

一覧は200件、保管履歴は100件ずつ表示します。検索・名前/更新日時/サイズの並べ替えは未表示分も対象です。サブフォルダを含める場合は一覧の **≣** を使います。索引は名前・日時・サイズだけを走査してSQLiteへ保存し、画像情報とサムネイルは表示ページ・表示範囲に絞ります。サムネイル生成は同時2件です。

新しく生成・移動した画像は **⟳** で再走査してください。全選択した圧縮処理はサーバー側で指定並列数ずつ処理し、100件の上限はありません。1万枚超の専用テスト画像で確認しましたが、ネットワークドライブや10万枚以上は未測定です。全処理時間は枚数・解像度・画面内容・ディスク速度で変わります。

## データ

ComfyUIのユーザーディレクトリ内 `asset-hub/` に保管記録 `records.sqlite3`、処理対象・完了・失敗・設定の `jobs.sqlite3`、登録フォルダ `folders.json`、索引 `catalog/`、未採用候補 `staging/`、展開PNG `cache/` を保存します。旧 `records.json` は初回に自動移行し、元ファイルは残します。

WebPと保管記録はセットで必要です。バックアップはComfyUI停止中にWebPと `asset-hub/` を保存してください。実行中のSQLiteは `-wal` に未反映のデータを含む場合があります。

保管DBの記録は可逆圧縮して保存します。既存DBは更新後の **ComfyUI再起動時**、素材庫が処理を受け付ける前に自動移行します。移行前DBを `asset-hub/records-before-compression-*.sqlite3.gz` へ退避して展開照合し、全記録の一致を確認してからDBを詰め直します。画像ファイルとジョブの進捗は変更しません。初回起動に追加時間がかかり、進行状況・完了・DBとバックアップの容量はComfyUIのログへ出します。

移行開始にはDBとWALの合計サイズの約3倍＋64MiBの空き領域を確保します。足りない場合は従来形式で継続し、次回起動時に再試行します。記録変換後に容量整理だけが中断した場合は、次回に容量整理から再開します。退避バックアップは自動削除しません。旧版アプリは新しい圧縮記録を読めず、退避DBは移行時点の内容で、その後の保管分を含みません。


- 対象は静止画の8bit RGB/RGBA PNG。16bit・パレット・APNGなどは品質を落とさず対象外とします。
- workflow/promptをWebPへ埋め込み、PNGの付随チャンクを保管記録に残します。元PNGの全バイト列を保存する方式ではありません。
- 同名ファイルは上書きせず、変換後に原本や保管ファイルが更新されていれば処理を止めます。
- PNGのファイル名がWebPへ変わります。元PNGパスを参照する処理ではPNGに戻して使います。
- 展開キャッシュは最大512MB（復元処理中に使用しているファイルは削除せず、処理後に調整）。別途ダウンロードしたPNGやサムネイル、索引は別の容量です。
- 強制終了したバッチは処理履歴から再開できます。照合不能な途中ファイルや、外部から変更されたファイルは自動で削除・上書きせず失敗理由を表示します。圧縮中の強制終了で、未登録の一時候補が残る場合があります。

## 開発と検証

処理の分担は次のとおりです。APIや画面を変更する場合も、圧縮・照合・復元の処理は共通です。

| ファイル | 責務 |
| --- | --- |
| `hub_api.py` | ComfyUIのHTTP API、入力受付、応答 |
| `job_manager.py` | ジョブの開始・待ち行列・停止・再開、実行中の設定反映 |
| `job_store.py` / `jobs.py` | SQLiteへの完了記録と再開対象の管理 / 並列実行 |
| `storage.py` / `native_webp.py` | 画像・生成情報の照合と安全な置換・復元 / ネイティブコーデック |
| `record_codec.py` / `database_migration.py` | 旧JSONと圧縮記録の読み書き / 起動時の退避・照合・DB整理 |
| `src/hub.ts` | 画面操作とAPI通信、一覧・履歴の連携 |
| `src/progress-panel.ts` / `src/progress.ts` | 進捗の描画 / 表示文言と直近速度の計算 |
| `src/hub-styles.ts` | 素材庫のスタイル |

Node.js 22以降、Python 3.11以降を使用してください。PythonのテストにはComfyUIと同じPillow・NumPy・psutil環境を使います。

```sh
npm ci
npm run build
npm run test:progress
python -m unittest discover -s tests -v
python scripts/release.py check
```

別のComfyUIへコピーする場合は、インストール先を明示します。既存ユーザーデータやComfyUIの依存関係を変更せず、自動再起動もしません。`--dry-run` でコピー先と件数を確認できます。

```sh
python scripts/install.py --comfy-root /path/to/ComfyUI --dry-run
python scripts/install.py --comfy-root /path/to/ComfyUI
```

実UIテストでは、`COMFYUI_ROOT` にテスト対象のComfyUI、必要なら `COMFYUI_PYTHON` にそのPython実行ファイルを指定してください。環境変数は自分のシェルで設定し、実パスをリポジトリへ保存しないでください。既定のPythonパスはWindowsでは `venv/Scripts/python.exe`、その他は `venv/bin/python` です。対象ComfyUIに本拡張を配置してから実行します。

```sh
npm run qa
npm run qa:selection
npm run qa:scale
npm run qa:resume
npm run qa:space
npm run qa:cpu
npm run qa:entry
npm run qa:relations
```

Chromeが必要です。検証スクリプトは非表示Chromeと独立したCPU版ComfyUIを使用し、合成画像と出力は `outputs/` に作成します。既定のポート8190は `ASSET_HUB_QA_PORT` で変更でき、使用中なら終了します。起動した検証プロセスだけを終了し、既存ComfyUIや生成処理を止めません。Windows用コーデックを確認する項目があり、全E2Eの他OS対応を確認したものではありません。
